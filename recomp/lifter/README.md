# recomp/lifter – A64 decoder and lifter (P2.3)

Translates AArch64 functions (ARMv8.0-A, integer, loads/stores, branches, system) into C++.

| File | Content |
|---|---|
| `include/lgp/recomp/a64.hpp`, `src/a64_decode.cpp` | The project's one A64 decoder: `lgp::recomp::a64::decode(raw, pc)` → `Inst` (op, operands, `Flow`, `Invalid` reason) |
| `include/lgp/recomp/lifter.hpp`, `src/lifter.cpp` | `Lifter`: takes `LiftFunction {entry, blocks, indirect_targets}` (from the CFG, P2.2) and emits one C++ function per guest function |
| `include/lgp/lifted/` | Headers for the **generated** code: `CpuState`, helpers (flags, division, CRC, bit ops), runtime contract (`lifted.hpp`) |

Generated code only sees the macros from `lgp/lifted/lifted.hpp` (`lgp_mem_*`, `LGP_CALL_INDIRECT`,
`LGP_JUMP_INDIRECT`, `LGP_SVC`, …). The runtime behind them is selected by `LGP_RUNTIME_HEADER` (default
`lgp/runtime/guest.hpp`, arrives with P2.6); the tests bring their own mini runtime (`tests/lifter/guest_stub.hpp`).

Whole modules (analysis from `recomp/core` → lifter → C++ with dispatch entries) are generated by `recomp/codegen` or the CLI
`lgp_lift` (P2.5). `LiftOptions::setjmp_entries` turns `BL setjmp` into the host variant `LGP_SETJMP()` (ADR-0004).
Game code is never lifted in the repo; code generated from game code belongs in `$LGP_PRIVATE_DIR`.

Tests: `ctest --preset default -L lifter` (decoder unit tests, ~5,000 differential cases against Unicorn,
decoder fuzz with 200,000 words). Knowledge docs: `docs/knowledge/a64-*.md`, `lifter-muster.md`, `unicorn-als-orakel.md`.
