# P1.6 – Decision paper ADR-0001 to 0005

**Result: Paul accepted all five ADRs unchanged on 2026-10-10.**

As of: 2026-10-10 · Basis: measurement data from P1.1–P1.5 (`docs/analysis/01`–`04`) · Decides: Paul

All five ADRs have the measurement data entered; the recommendations were checked against it and adjusted where necessary. Status
stays **Proposed** until Paul approves. Details and counter-arguments are in the section "Critical review"
of each ADR.

| ADR | Recommendation | Main rationale (measured value) | Main risk | compared to the draft |
|---|---|---|---|---|
| [0001](0001-gast-adressraum-wasm.md) Guest address space | **wasm32** with a compact guest layout < 4 GiB (same on desktop and web), accesses only via macros, `TotalMemorySize` as a switch (web: 3072 MiB since 2026-10-11, before that 2.75 GiB) | Real need up to Route 1 is **1.29–2.55 GiB**; the 3.14 GiB heap is only "everything that is reported" | LGP does not run stably with less reported memory (gate in P3.1/P3.3, otherwise re-evaluate memory64); CPU writes to GPU memory must be detected in Wasm without page protection | same, gate made more precise |
| [0002](0002-threads.md) Threads | **1:1 real threads** + switchable baton mode, new with a **core model** (max. one running guest thread per guest core) | 10–11 threads in the game, 3 with load; ≈ 30,000 kernel sync operations/s make cooperative scheduling (Asyncify) unsuitable | Code relies on Horizon core semantics (`GetCurrentProcessorNumber` 4,800/s); WebGPU from workers unchecked per browser | same, core model added |
| [0003](0003-grafik-hle-lle.md) Graphics | **NVN HLE** via the proc slots + **offline shaders** with a runtime fallback; deswizzle textures offline, ASTC → BC7 | NVN only via bootstrap loader, **230 of 498** functions used, driver implementations findable in `sdk`; **95 %** of the runtime shaders are byte-identical in the data, no glslc | NVN structures not yet understood (abort criterion in P4.1, then re-evaluate LLE); 27 shaders of unknown origin | same, gate 2/3 met, third criterion becomes an abort criterion |
| [0004](0004-indirekte-spruenge.md) Indirect jumps | **Function = C++ function**, native return, **directly indexed dispatch table over all functions**, one jump table recognizer, `musttail` for tail calls, `setjmp`/`longjmp` via a host variant, no interpreter | 0 `RET` ≠ `x30`, no exceptions in `main`, no dynamic code; 61 % of functions address-taken, 109,000 `BLR` → lookup must be O(1) | Host stack grows with tail call chains (remedy `musttail`, check Wasm tail calls before P6.1); table costs 18–29 MiB of Wasm memory | made more precise; block dispatcher (C) probably unnecessary |
| [0005](0005-sdk-nsos.md) `sdk`/`subsdk*` | **Recompile `main` + `sdk`**, SVC/IPC as the HLE boundary; do **not** recompile `subsdk0` (glslc) and `subsdk1` (video), but replace their 8 and 28 imports; targeted replacements by symbol (NVN, `memcpy`/`memset`, TLS, `setjmp`) | `subsdk0`/`subsdk1` = 39 % of the code, but only provide module init or the intro video; the 21 services used are well documented via Ryujinx (MIT), re-creating `sdk` at API level would mean more guesswork | An SDK path does throw C++ exceptions after all (a loud abort will show it); later parts of the game do need `subsdk*` after all | **changed**: no longer recompile "everything" (≈ 4.6 instead of 7.4 million instructions) |

## Dependencies between the decisions

- 0001 ↔ 0004: the dispatch table lives in the same 4 GiB memory (18 MiB for `main` + `sdk`).
- 0001 ↔ 0003: how CPU writes to GPU memory are detected is decided in P4.1; the memory abstraction keeps a switchable page-flag path free for it.
- 0002 ↔ 0005: because `sdk` is recompiled too, the sync operations go through SVC runtime calls (no trap); that is enough for ≈ 30,000/s.
- 0003 ↔ 0005: NVN HLE replaces the NVN driver in `sdk`; `nvdrv`/binder will probably only need stubs for graphics.

## What remains open (not relevant to the decision, but not measured)

- Browser facts (wasm32 memory with `SharedArrayBuffer`, WebGPU in workers, Wasm tail calls, memory64 in Safari) come
  from secondary sources and will be measured on Paul's devices in P6.1.
